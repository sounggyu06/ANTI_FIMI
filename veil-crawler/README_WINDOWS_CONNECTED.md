# Windows 통합 실행

다음 폴더를 함께 유지합니다. D4D 폴더 전체를 다른 위치에 옮겨도 상대 경로로 연결됩니다.

```text
D4D/
  START_ANTI_FIMI.cmd
  STOP_ANTI_FIMI.cmd
  ANTI_FIMI/
  ANTI_FIMI_DEMO_DATA/
  fimi-dashboard/dist/
  veil-crawler/
```

Python 3.12와 Node.js 22.13 이상이 필요합니다. 첫 실행은 인터넷으로 라이브러리를 설치하며, 이후에는 로컬 사이트·엔진으로 동작합니다. Python Launcher의 `py -3.12` 명령을 사용할 수 있어야 합니다.

1. D4D의 `START_ANTI_FIMI.cmd`를 실행합니다.
2. 수집 준비가 끝나면 사이트와 대시보드가 열립니다. 기본 주소는 사이트 `http://127.0.0.1:5180/`, 대시보드 `http://127.0.0.1:8788/`입니다.
3. 사이트에서 전시 시뮬레이션을 시작합니다. 전시 게시물은 실제 공개 시각으로 0.1~0.4초 간격에 한 개씩 생성합니다. 기존 배경 게시물은 첫 수집 시 기준 목록으로 기록하여 새 시연 분석에서 제외합니다.
4. 빈 상태부터 다시 시작하려면 대시보드의 **새 시연**을 사용합니다. 연결된 사이트를 정지·초기화하고 수집 기준을 새로 설정합니다. 운용표와 이전 시연 기록은 보존합니다.
5. 종료는 D4D의 `STOP_ANTI_FIMI.cmd` 또는 실행 창의 Ctrl+C를 사용합니다. 이 실행에서 시작한 엔진·수집기·사이트 프로세스만 종료합니다. 별도 실행 중이던 사이트를 재사용한 경우 그 사이트는 유지합니다.

실행 창은 연결 중 계속 켜두세요. 중복 실행과 포트 충돌은 안내하고 중단하며, 기존 서버 PID를 찾아 강제로 종료하지 않습니다. 기존 8787 대시보드와 별개로 8788을 사용합니다.

로그는 `veil-crawler/runtime/connected-web.log`, `connected-engine.log`와 엔진 데이터 폴더의 수집 로그에 남습니다. 웹 데이터는 `runtime/web-data`, 로컬 아카이브는 `runtime/archive`, 엔진 연결 데이터는 `ANTI_FIMI_DEMO_DATA/ANTI_FIMI_veil_live.sqlite3` 및 해당 시연 저장소에 보관합니다.

## 개발 위치에서 실행

```powershell
py -3.12 -X utf8 .\run_connected.py --d4d "C:\경로\D4D" --no-browser --no-pause
py -3.12 -X utf8 .\run_connected.py --stop --no-pause
```

별도 포트가 필요하면 `--site-port 5181 --engine-port 8789`를 추가합니다. 같은 폴더에서 `run_web.py`로 실행한 사이트가 이미 있으면 확인 후 재사용하므로 실제 사이트 포트는 달라질 수 있습니다.

다른 PC로 옮긴 가상환경이 이전 Python 설치 경로를 가리키면 기존 환경을 `.venv.previous-번호`로 보존하고 현재 PC용으로 재생성합니다. 설치 시에는 위치가 고정된 pip 실행 파일 대신 `python -m pip`를 사용합니다. 환경 자체가 손상돼 실행되지 않으면 `crawler/.venv`를 프로젝트 밖으로 옮긴 뒤 다시 실행하세요. Mac 가상환경과 Mac용 node_modules를 가져오지 마세요.

## 수집·탐지 범위

- 통합 연결은 공개 `/posts` HTML에서 게시물·계정 ID, 밀리초가 포함된 작성 시각, 본문, 언어, URL, 인용·재게시·답글 원본 ID만 가져옵니다. 시나리오 정답·숨은 역할·사전 라벨을 엔진에 전달하지 않습니다.
- 0.5초마다 확인하므로 여러 개가 한 번의 전송에 묶일 수 있습니다. 사이트의 설정 간격 100~400ms와 실제 작성 시각은 유지됩니다. 파일 저장·잠금 복구가 추가로 걸리므로 실제 간격을 엄격히 보장하는 실시간 시스템은 아닙니다. 네트워크/엔진 지연은 전송 대기열에 쌓이고 재시작하면 동일 내용으로 재전송합니다.
- 초기 배경 게시물은 기준 목록으로 제외합니다. 기준 목록에만 있는 원문을 나중에 참조하면 원문 작성자를 추정하지 않습니다. 새 게시물 간 참조는 원본 ID로 연결합니다.
- AI 없는 모드이므로 URL·원본 참조·동일 문구로 자료를 묶고 행동을 분석합니다. 다국어 의미·입장·허위성·배후를 판정하지 않습니다. 자료 묶음과 검토 후보가 곧 공작 확정은 아닙니다.
- 전시 시나리오는 현재 시각과 100~400ms 간격입니다. 기존 재난구호 시나리오는 과거 시간 패턴 재현 방식입니다.
- 확산 추세 비교에는 최소 10분의 자료가 필요합니다. 짧은 시연의 '자료 축적 중'은 정상이며 경보 발생을 보장하지 않습니다. 전체 전시 시나리오 검증에서는 1,801개 게시물과 1,419개 원문 참조를 누락 없이 저장했고 행동 검토 후보 2건이 발생했습니다. 이는 합성 시나리오 연결 검증이며 탐지 정확도 측정은 아닙니다.
- 시작은 기존 엔진 시연을 복원합니다. 매 시연을 빈 상태로 시작하려면 **새 시연 → VEIL 수집 중 확인 → 사이트 시나리오 시작** 순서로 실행하세요.
- 종료한 뒤 D4D 전체를 옮기세요. ZIP에는 설치된 node_modules/가상환경/실행 잠금 파일을 제외하며 첫 실행에서 Windows 환경을 재구성합니다. Python 3.12·Node.js는 이동한 컴퓨터에도 설치되어 있어야 합니다.
