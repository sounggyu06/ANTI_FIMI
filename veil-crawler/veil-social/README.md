# VEIL Social — 기존 시뮬레이션 SNS

사용자 제공 실제 X 게시물과 로컬 사진을 표시합니다. 시작 버튼을 눌렀을 때 가상 대한민국·APAC 재난구호 협력 취소설의 확산을 재현합니다. 실제 글의 진위는 미판정으로 유지합니다.

## 실행

상위 폴더의 `run_web.py` 또는 Windows용 `start_web.cmd`를 실행하세요. 패키지 설치·빌드·서버 실행·브라우저 열기를 자동 처리합니다. 탐지 엔진과 함께 실행하려면 D4D의 `START_ANTI_FIMI.cmd`를 사용하세요. 자세한 사용 순서는 상위 README에 있습니다.

수동 실행도 가능합니다. Node.js 22.13 이상이 필요합니다.

```bash
npm ci
npm run build
npm start
```

수동 실행의 기본 주소는 http://127.0.0.1:5173/ 입니다. Python 실행 파일은 사용 중인 포트 대신 다른 포트를 선택하고 크롤러에 전달합니다. 종료는 실행 터미널에서 Ctrl+C입니다.

## 실제 게시물과 사진

`data/imported-x/`의 사용자 수집 JSONL 7개와 첨부 사진 파일 69개를 시작 시 공통 SQLite 저장소에 이식합니다. 중복 원문 ID를 합쳐 고유 게시물 113개입니다. 본문·작성 시각·작성자·핸들·원문 링크를 보존하고 사진은 바이트 그대로 복사합니다. 원본을 수정하거나 새로 다운로드하지 않습니다.

누락된 좋아요·재게시 수는 화면에 —와 미수집 안내로 표시합니다. 크롤러 숫자 출력은 누락 기본값 0입니다. 진위는 자동 판정하지 않습니다.

기본 저장소는 상위 프로젝트의 `runtime/archive/`입니다. 추가 로컬 자료는 JSONL과 images 폴더를 같은 데이터 폴더에 넣어 가져오고 웹을 재시작하면 반영합니다.

```bash
npm run import:local -- --directory "/절대경로/x-crawler/data"
```

전체 누적 자료 내보내기는 `npm run export:x`를 사용합니다. 시작 피드는 최근 200개를 먼저 불러오며 웹 API와 수집 HTML은 누락된 보관 이력을 같은 DB에서 추가해 전체 프로필 게시물을 제공합니다. 원본은 DB에 유지합니다. X 가져오기/자동 수집/저장 데이터 불러오기 UI는 제거한 상태입니다. 기존 공식 API 연결용 백엔드는 유지하지만 두 Python 실행 파일은 X API 수집을 시작하지 않습니다.

## 시작 상태와 가상 시나리오

서버를 새로 시작하면 이전 시나리오 글을 제거하고 준비 상태로 돌아갑니다. 실제 게시물은 유지하며 순서를 한 번 섞습니다. 화면 갱신 때마다 다시 섞지 않습니다.

**시나리오 시작**을 눌러야 가상 허위 주장과 부정 사진이 등장합니다. 일반 모드는 4초, 빠른 모드는 0.75초마다 의견 재게시 4개를 생성하며 15단계 동안 첫 글 1개·재게시 60개·별도 허위 주장 12개를 생성합니다. 좋아요 증가도 합성된 실험 값입니다. 동조·질문·검증·반박·풍자 의견이 섞이며 재게시 자체가 악의적 행위라는 뜻은 아닙니다. 긍정 뉴스를 합성하지 않습니다.

중지는 확산을 멈추고 테스트 초기화는 시나리오 글만 제거합니다. 첫 게시물 보기와 사진 확대를 지원합니다.

## 크롤러 연결

GET `/posts`는 같은 서버의 현재 피드를 HTML로 제공합니다. React 화면 `/`와 동일한 저장소를 읽으므로 별도 테스트 사이트가 필요하지 않습니다. requests + BeautifulSoup으로 JavaScript 실행 없이 수집합니다.

상위 `run_crawler.py` 또는 `start_crawler.cmd`를 실행하면 현재 서버에 연결하고 `crawler/output/raw_posts_실행시각.jsonl`에 저장합니다. 최종 JSONL에는 기존 6필드만 넣습니다. 지속 수집은 `run_connected.py`에서 별도로 실행하며 게시물·관계 ID를 유지합니다.

`npm test`는 시나리오, 시작 초기화·순서 섞기, 로컬 자료 병합·저장, 기존 API 수집기의 모의 응답 처리를 검증합니다. 이번 실행 검증에서 외부 X API는 호출하지 않습니다.

## 서버 익명화 경계

`anonymizer.mjs`는 `anonymized_users.json`을 서버 저장소에 보관하며 공개 게시물과 프로필을 허용된 필드만으로 다시 구성합니다. 실제 작성자 프로필 사진, 원본 사용자 ID·게시물 ID, 원문 URL, 로컬 파일명과 simulation_role을 브라우저에 전달하지 않습니다. 프로필은 `src/post-utils.mjs`의 postsByUser 함수로 같은 익명 ID의 게시물을 필터링합니다. JSONL 원본은 변경하지 않습니다.

GET `/api/me`: 현재 데모 작성자의 익명 프로필. GET `/api/profiles/anon_0001`: 프로필 메타데이터와 게시물 수. 실제 게시물은 타임라인과 프로필이 공통으로 사용하는 GET `/api/posts` 배열에서 읽습니다. 프로필용 게시물 저장본을 복제하지 않습니다.

매핑 파일은 같은 공통 저장소를 사용하는 재시작에서 유지됩니다. ID가 제공되면 작성자 이름 변경에도 연결하고, ID가 없으면 고유 핸들을 사용합니다. ID와 핸들이 모두 없는 자료는 표시 이름만으로 동명이인을 합치지 않습니다. 기존 6필드 JSONL의 author_id도 지원합니다.

## 시간 생성과 검사

`simulation.mjs`는 화면 생성 속도를 담당하고 `temporal.mjs`는 가상 사건의 시간표를 담당합니다. 6가지 시간 패턴과 계정별 활동 설정을 결합하며 실제 입력 자료의 시각을 변경하지 않습니다. 계정 역할은 시간 생성 함수의 입력이 아닙니다. 같은 계정의 익명 매핑과 프로필 연결은 유지합니다.

POST `/api/simulation/start`와 `/api/simulation/start-fast`는 선택적 JSON body `{"pattern":"double_peak"}`를 받습니다. 생략하면 자동 선택입니다. 기존 `X-Veil-Client: demo` 헤더가 필요하며 지원하지 않는 패턴은 HTTP 400, 준비 상태가 아니면 HTTP 409입니다. seed와 상세 계정 설정은 서버 내부 상태에만 저장합니다.

`temporal-quality.mjs`는 시간 품질 통계와 시나리오 비교 함수이며 `report-temporal.mjs`는 실제 입력 및 12개 재현 가능한 시나리오를 검사하는 CLI입니다. 상위 `check_time_quality.py`는 현재 저장 데이터도 포함하고 설치 환경을 자동 준비합니다. 결과는 상위 `reports/`에 저장하며 웹으로 공개하지 않습니다. 크롤러의 6필드 출력 계약은 변경하지 않습니다.
