# VEIL Social — Windows 실행

테스트 웹과 크롤러, ANTI_FIMI 탐지 엔진을 연결합니다. 필요한 패키지 설치와 웹 빌드는 자동으로 처리합니다. Python 3.12와 Node.js 22.13 이상을 먼저 설치하세요.

## 사이트·크롤러·탐지 엔진 함께 실행

이 폴더를 D4D 안의 `veil-crawler`로 두고 D4D의 `START_ANTI_FIMI.cmd`를 실행하세요. 수집 준비 후 사이트와 대시보드가 열립니다. 사이트에서 시뮬레이션을 시작하면 이후 공개되는 글을 지속 수집합니다. 새 시연은 대시보드에서, 종료는 `STOP_ANTI_FIMI.cmd`에서 실행합니다. 이전 8787 서버는 건드리지 않으며 연결 대시보드 기본 포트는 8788입니다.

폴더 이동·로그·개발 실행·종료 방식은 [Windows 통합 실행 안내](README_WINDOWS_CONNECTED.md)를 참고하세요. 통합 실행은 `crawler/live.py`를 사용하며 게시물 ID와 관계 ID를 보존합니다. 아래 단독 크롤러는 기존 6필드 JSONL 출력을 유지합니다.

## 웹과 일회 수집을 따로 실행

1. ZIP 전체를 압축 해제하고 폴더 안 파일을 함께 둡니다.
2. `start_web.cmd`를 더블 클릭합니다. 웹이 준비되면 브라우저가 자동으로 열립니다. 이 터미널 창은 켜둡니다.
3. 필요한 시점에 `start_crawler.cmd`를 더블 클릭합니다. 현재 웹 게시물을 한 번 수집합니다.
4. 결과는 `crawler/output/raw_posts_YYYYMMDD_HHMMSS_ffffff.jsonl`에서 확인합니다.

시나리오 글도 수집하려면 웹의 **시나리오 시작**을 누르고 크롤러를 실행하세요. 크롤러는 시나리오를 자동 시작하지 않습니다. 실행 시각(KST)을 파일명에 넣어 매번 새 파일을 저장하므로 이전 결과도 유지됩니다. 끝의 6자리는 마이크로초로, 같은 초에 여러 번 실행해도 구분됩니다.

## Python 실행

프로젝트 최상위 폴더의 두 파일을 별도 터미널에서 실행합니다.

```powershell
py -3.12 -X utf8 .\run_web.py
```

```powershell
py -3.12 -X utf8 .\run_crawler.py
```

- `run_web.py`: 웹 패키지 설치 → 변경 시 빌드 → 서버 시작 → 브라우저 열기. 웹을 유지하며 종료는 해당 터미널에서 Ctrl+C입니다.
- `run_crawler.py`: 크롤러 가상환경 및 패키지 준비 → 현재 웹의 HTML 수집 → JSONL 저장 → 통계 표시.
- `.cmd` 파일은 Windows에서 위 Python 파일을 실행하는 바로가기입니다.

Windows 실행 파일은 Python **3.12**, Node.js **22.13 이상**을 사용합니다. 처음 패키지를 설치할 때 인터넷이 필요합니다. 설치 후에는 로컬에 저장한 게시물과 사진으로 실행합니다. ZIP 안에서 직접 실행하지 말고 압축 해제한 폴더를 사용하세요.

- 시작 시 이전 가상 시나리오 글을 정리하고 **준비** 상태로 시작합니다. 실제 수집 게시물은 유지합니다.
- ‘영화 · 책 · 뉴스 · 시사 · 이슈’ 제목과 X 가져오기/자동 수집/저장 데이터 불러오기 영역을 제거했습니다. 게시물 첨부 사진은 유지합니다.
- 5173 포트에 다른 서버가 있으면 빈 포트를 선택합니다. 크롤러는 같은 폴더의 웹이 기록한 주소에 자동 연결합니다. 다른 서버를 종료하지 않습니다.

## 구조와 저장 위치

```text
veil-crawler/
├── run_web.py                 테스트 웹 실행
├── run_crawler.py             HTML 크롤링 실행
├── check_time_quality.py      시간 품질 보고서 생성 (선택)
├── reports/                   현재 데이터·시나리오 비교 보고서
├── launcher_utils.py          공통 설치·연결·실행 잠금
├── run_connected.py           사이트·엔진·지속 수집 통합 실행
├── start_connected.cmd        Windows 통합 실행
├── stop_connected.cmd         통합 실행 종료 요청
├── start_web.cmd              Windows 웹 단독 실행
├── start_crawler.cmd          Windows 일회 크롤링 실행
├── veil-social/               Node/React 시뮬레이터, 원본 게시물과 사진
├── crawler/                   requests + BeautifulSoup 크롤러
│   ├── config.py              HTML selector·저장 경로
│   ├── output/raw_posts_YYYYMMDD_HHMMSS_ffffff.jsonl 수집 결과
│   └── logs/crawler.log       수집 로그 (실행 시 생성)
├── runtime/                   연결 정보·웹 로그 (실행 시 생성)
└── tests/                     실행 파일 검증
```

웹 연결 정보는 `runtime/web-instance.json`, 웹 로그는 `runtime/web.log`에 저장합니다. 화면용 상태는 프로젝트의 `runtime/web-data/`를 사용합니다. 실제 게시물과 사진은 기본적으로 프로젝트의 `runtime/archive/`에 보존합니다. 다른 컴퓨터로 누적 자료까지 옮길 때는 서버 종료 후 D4D 폴더 전체를 복사하세요. 이전 폴더의 연결 메타데이터는 프로젝트 경로와 서버 세션을 검증하며, 다른 위치의 서버에 자동 연결하지 않습니다.

사용자가 제공한 JSONL 7개, 고유 게시물 113개와 첨부 사진 파일 69개가 포함되어 있습니다. 원본에 없는 반응 수는 크롤러 출력에서 기본값 0을 사용하며 실제 0건으로 확인한 값은 아닙니다.

## JSONL 형식

UTF-8로 게시물 하나당 한 줄, 아래 6개 필드를 저장합니다. 다음은 형식 설명용 예시입니다.

```jsonl
{"author_id":"user_001","comment":"false","created_at":"2026-10-10T14:00:00+09:00","text":"게시글 본문","retweet_count":3,"like_count":12}
```

`author_id`는 원본 X ID 대신 공개 익명 ID(예: anon_0001)입니다.

`comment`는 댓글/답글 여부를 나타내는 문자열 true/false입니다. 진위 판정이 아닙니다. 두 반응 수는 정수이며 이미지 URL은 이 6필드 양식에 넣지 않습니다. 사진은 시뮬레이터 데이터에 보존합니다. 크롤러는 수집과 정규화만 수행합니다.

## 설정 및 문제 확인

HTML 구조가 바뀌면 `crawler/config.py`의 `SELECTORS`, `ATTRIBUTES`를 변경하세요. 현재 `article.post`, `.post-content`, `time.post-time`, `.like-count` 및 게시물 속성 `data-author-id`, `data-comment`, `data-reposts`를 읽습니다. 웹 주소와 단일 페이지 모드는 실행 파일이 자동 전달합니다.

‘먼저 같은 폴더의 run_web.py를 실행’이라는 안내가 나오면 새 압축 해제 폴더의 웹부터 실행하세요. 예전 프로젝트의 웹만 켜둔 경우 자동 연결하지 않습니다. 웹 실행 실패는 `runtime/web.log`, 수집 오류는 `crawler/logs/crawler.log`에서 확인합니다. 처음 설치 실패 시 네트워크와 표시된 오류를 확인한 뒤 다시 실행하세요.

개별 크롤러 옵션은 `crawler/README.md`, 시뮬레이터 설명은 `veil-social/README.md`를 참고하세요.

## 익명 계정과 프로필

- 원본 작성자 이름·핸들·사용자 ID·프로필 링크는 서버 내부 자료에만 보존합니다. 웹 API, 수집 HTML, 웹 JSONL 내보내기는 익명 계정과 가려진 원문 링크를 제공합니다.
- 같은 작성자의 글은 같은 anonymous_user_id로 연결하며, 닉네임·username·이니셜 아바타·색상이 고정됩니다.
- 계정 매핑은 `runtime/archive/anonymized_users.json`에 보관하며 웹에서 제공하지 않습니다. Windows 파일 접근 권한은 해당 폴더의 ACL을 따릅니다. 이 파일을 삭제하면 기존 익명 ID를 유지할 수 없습니다. 다른 컴퓨터로 옮길 때 저장소 전체와 함께 보관하세요.
- 아바타·닉네임·@username을 누르면 `/profile/anon_0001` 같은 프로필로 이동합니다. 원본 작성자명이 아니라 익명 ID로 같은 게시물 배열에서 이력을 찾습니다. 없는 계정은 404 화면, 글이 없는 계정은 빈 상태로 표시합니다.
- 시나리오는 두 행위자가 관련 주장을 반복 작성하고 여러 관찰 계정이 60개의 의견 재게시를 작성하는 방식입니다. 기본 시나리오를 완료하면 두 행위자의 이력은 7개·6개이며, 프로필의 수는 저장된 데이터에서 계산합니다. 가상 역할은 내부 simulation_role 필드로만 저장합니다.
- 일반 시연은 4초 간격, 빠른 시연은 0.75초 간격으로 화면에 등장합니다. 이 실행 속도는 가상 작성 시각과 독립적이며, 작성 시각은 아래 시간 패턴을 따릅니다. 실제 게시물의 원래 작성 시간은 유지합니다.
- 수집 게시물의 프로필 사진은 사용하지 않습니다. 게시물 첨부 사진은 보존하며 사진 안의 얼굴·글자와 본문 전체의 개인정보를 자동으로 탐지/블러 처리하는 기능은 없습니다. 현재 처리는 작성자 식별 필드, 알려진 작성자명/핸들, 계정 멘션과 X/단축 원문 링크에 적용됩니다.
- 원본 JSONL과 서버 DB는 익명화 이전 자료를 보존하므로 서버 내부 자료로 관리하세요. 웹 내보내기는 익명화되어 있지만 `npm run export:x`는 내부 원본 보관용입니다.

수정 전 서버가 켜져 있다면 Ctrl+C로 종료한 뒤 `start_web.cmd` 또는 `run_web.py`를 다시 실행하세요. 새 프론트엔드는 예전 서버의 익명화되지 않은 게시물 응답을 표시하지 않고 재시작 안내를 보여줍니다.

## 현실적인 가상 작성 시각과 빠른 시작

아래 시간 패턴은 기존 재난구호 시나리오에만 적용됩니다. 전시 복합 위기는 실제 현재 시각으로 한 글씩 게시하며, 매번 0.1~0.4초의 무작위 간격을 사용합니다. 전시 시나리오의 빠른 생성 버튼은 제공하지 않습니다.

웹에서 **시간 패턴**을 선택한 뒤 **시나리오 시작** 또는 **빠른 시나리오 시작 · 15초 이내**를 누릅니다. 자동 선택은 실행마다 새로운 seed와 패턴을 사용합니다. 테스트 초기화 후 다른 패턴으로 다시 실험할 수 있습니다.

- 급격한 집중 (`rapid_spike`): 사건 직후 높은 반응과 감소.
- 점진적 증가 (`gradual_growth`): 시간이 지나면서 참여가 증가하고 감소.
- 두 번의 집중 (`double_peak`): 첫 이슈와 후속 이슈 주변에 각각 참여.
- 지연된 집중 (`delayed_spike`): 늦게 집중되는 반응.
- 오래 이어지는 반응 (`long_tail`): 초기 반응 이후 오래 이어지는 참여.
- 낮은 활동량 (`low_activity`): 긴 관찰 기간에 낮은 평균 게시율.

한 시나리오는 기존과 같이 원문 1개, 의견 재게시 60개, 관련 주장 12개를 만듭니다. 비교를 위해 개수는 유지하지만 작성 시간의 집중도와 기간은 달라집니다. 일반 관찰 계정도 반복 참여하므로 같은 익명 프로필에 여러 글이 연결됩니다.

**실제 생성 시간과 가상 사건 시간은 다릅니다.** 빠른 모드는 로컬 실행 검증에서 약 11.3초 만에 73개를 생성했지만 가상 작성 시각은 여러 시간에 걸쳐 있습니다. 사건 시작은 최근 며칠 중에서 선택하고 전체 가상 시간표가 현재 이전에 끝나도록 구성합니다. 실행이 시작된 실시간은 `startedAt`, 글의 가상 시각은 `publishedAt` 및 크롤러 `created_at`입니다.

시간 생성은 사건별 활동 강도, 한국 시간대의 활동량, lognormal·gamma 기반 지연/간격과 jitter를 결합합니다. 계정별 `active_hours`, `posting_frequency`, `burst_probability`, `response_delay`와 후발 참여 여부를 생성합니다. 역할은 이 생성식의 입력으로 사용하지 않으며 활동 시간은 고정 제약이 아닌 가중치입니다. 실제 수집 자료의 `created_at`은 재생성하지 않습니다.

계정 활동 설정·seed·사건/후속 사건 시각·전체 시간표는 서버 내부 `runtime/web-data/simulation.json`의 `temporalPlan`에 저장됩니다. 게시물은 내부 `scenario_id`로 연결합니다. 원본 계정 대응 정보와 역할은 공개 API나 HTML에 전달하지 않습니다. 크롤러는 기존 6필드 JSONL을 그대로 출력하며 분석 기능을 추가하지 않았습니다.

### 시간 품질 검사

선택 사항으로 프로젝트 최상위에서 실행합니다.

```powershell
py -3.12 -X utf8 .\check_time_quality.py
```

현재 저장된 서버 게시물이 있으면 해당 데이터의 시간대별 개수·피크·동일 계정 중앙 게시 간격·burst·중복/빈 시각을 검사합니다. 동시에 6패턴을 각각 2번 생성하는 고정 seed 검증을 수행하고 이전 4초 고정 방식과 상대 시간 분포를 비교합니다. 서버를 켜지 않아도 포함된 실제 자료와 12개 시나리오로 검사할 수 있습니다. 원본과 현재 게시물을 수정하지 않습니다.

출력은 `reports/temporal-quality.md`, `reports/temporal-quality.json`입니다. JSON에는 현재 실제/가상 자료와 검증용 합성 자료를 구분하고, 시나리오별 시작·duration·피크·상대 12구간 histogram을 제공합니다. 계정별 통계의 식별자는 보고서용 번호입니다. 역할별 시간대·중앙 간격 분포의 겹침도 함께 확인합니다.

동일 분포는 사건 시작부터 설정 duration까지 상대 12구간의 게시물 개수 벡터가 완전히 같은 경우입니다. burst는 전체 피드에서 5분 이내 3개 이상인 겹치지 않는 구간입니다. 실제 게시물의 동일 작성 시각은 오류라고 간주해 바꾸지 않습니다. 중앙 게시 간격은 동일 계정의 시각을 정렬한 뒤 계산하며 전체 피드의 인접 게시물 간격과 다릅니다.

개발자가 재현할 때는 `veil-social/temporal.mjs`의 생성 함수를 `createTemporalPlan({pattern, seed, now})`로 호출합니다. `daytimeWeights`, `scenarioParameters`, `accountActivity`에서 시간대 가중치·기간/피크·계정 설정을 조절합니다. 실제 SNS 전체의 측정 분포에 보정한 모델은 아니므로 특정 시나리오 한 번의 결과보다 여러 seed와 역할별 겹침을 함께 살펴보세요.


## 전시 복합 위기 훈련

전시 게시 시각은 시작 시각 이후 실제 게시 순간의 현재 시각입니다. 다음 글의 대기 시간은 100~400밀리초 사이에서 새로 정합니다. 지연되더라도 한꺼번에 따라잡지 않습니다. 개요 1개와 후속 글 1,800개를 완료하는 평균 대기 시간은 약 7분 30초이며 저장·처리 시간은 추가될 수 있습니다. 이 변경은 새 실행부터 적용되므로 웹을 재시작하세요.

웹을 재시작하고 훈련 시나리오에서 전시 복합 위기를 선택하세요. 열 가지 이슈의 주장·질문·반박·공식 확인을 함께 생성합니다. 각 실행은 시나리오 주장 1,500개, 질문·반박·공식 확인 300개, 개요 1개를 생성합니다. 계정별 게시 수는 난수로 배분하며 소문과 중간 재게시에도 연결됩니다. 본문에는 자료 번호·훈련 접두어·예시 URL을 붙이지 않고 화면 상단의 연구용 표시를 유지합니다. 상세 설정과 기준 사실은 SCENARIO_WARTIME.md에 있습니다. 기존 수집 결과와 원본 자료는 보존합니다.
