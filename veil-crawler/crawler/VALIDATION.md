# 실제 사용자 수집 자료 이식 및 JSONL 검증

- 사용자 JSONL 5개, 입력 44개 레코드. 동일 원문 ID 1개를 합쳐 실제 게시물 43개로 이식. 원본 JSONL은 변경하지 않음.
- 원문 본문·표시 이름·계정 핸들·작성 시간·원문 링크를 전부 대조하여 일치 확인. 중복 게시물의 두 수집 주제도 보존함.
- 첨부 사진 44개는 원본 파일을 그대로 복사. 로컬 서버의 사진 응답을 SHA-256으로 원본과 비교하여 44개 모두 일치 확인. 외부 사진 다운로드 없음.
- 원본에 반응 수가 없으므로 화면은 미수집으로 표시하고 6필드 크롤러 출력의 정수값은 기본 0. 실제로 좋아요/재게시가 0건이라는 판단이 아님.
- 기존 Node 서버의 /posts HTML에서 43개 발견, 43개 저장, 경고 0개, 오류 0개. output/raw_posts.jsonl 생성 확인.
- 최종 필드와 순서: author_id, comment, created_at, text, retweet_count, like_count.
- comment는 문자열 false/true, retweet_count와 like_count는 정수. 구 출력의 이미지/제목/원문 ID 필드는 저장하지 않음.
- 시뮬레이션 초기화 후 43개 보존, 동일 저장소로 서버 재시작 후 게시물/사진 재사용 확인.
- 실제 사용 중인 공통 저장소에도 43개 이식하고 실행 중인 5173 서버의 피드에 반영함. 기존 시뮬레이션 73개 유지, 총 116개.
- Python 테스트 17개는 이전 형식 변경 검증에서 통과. Node 테스트 현재 23개 통과(로컬 가져오기·중복 제거·사진 제한·실제 값 유지·기존 확산 기능 포함).
- 외부 X API 호출, AI 분석, 진위 판정, 로그인/차단 우회 없음. 실제 게시물은 진위 미판정 상태로 표시함.
