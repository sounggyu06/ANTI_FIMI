# 새 시연 기능

대시보드 오른쪽 위 **새 시연 → 새 시연 시작**을 누릅니다. 취소하면 현재 기록을 유지합니다.

## 초기화 범위
- 현재 화면의 게시물·계정·자료 묶음·조사망·경보와 알림을 비웁니다.
- 기존 SQLite 파일은 삭제하지 않습니다. 새 기록은 `<기존 DB 이름>_sessions/<시연 ID>.sqlite3`에 저장합니다.
- `<기존 DB 파일>.active.json`은 현재 시연을 가리킵니다. 원래 실행 명령으로 서버를 다시 시작해도 이 파일을 읽어 현재 시연을 복원합니다.
- 운용표 XLSX, 탐지 설정, AI 사용 여부를 유지합니다. 이전 DB의 검증 자료도 그대로 남습니다.
- JSONL 감시는 초기화 시점에 존재한 게시물 ID를 제외하고 새로 추가된 글부터 처리합니다. 이미 시작된 불완전한 마지막 줄도 완료 시 제외합니다. 기존 게시물 ID를 새 게시물에 재사용하지 마세요.

## 외부 수집기 연결 규약
사이트·크롤러 자체 초기화는 이번 변경에 포함되지 않습니다. 새로 받을 사이트·크롤러 연결 시 아래 규약을 사용해야 합니다.

1. 사이트 시뮬레이션과 이전 수집 작업을 중지합니다.
2. 대시보드에서 새 시연을 시작합니다.
3. `GET /api/session` 응답의 `session.id`를 새 수집 실행에 고정합니다.
4. 사이트의 이전 게시물을 초기화하거나, 새 수집 시작 전에 존재한 ID를 수집기에서 제외합니다.
5. 새 수집의 `/api/posts` 요청에 `session_id`를 포함합니다. 전송 대기열에도 해당 ID를 함께 저장합니다.
6. HTTP 409는 시연 변경을 의미합니다. 이전 대기열을 새 ID로 바꿔 재전송하지 말고 이전 실행을 종료합니다.

요청 예시:
```json
{
  "session_id": "GET /api/session에서 받은 ID",
  "posts": [{
    "id": "unique-post-id",
    "account_id": "stable-account-id",
    "created_at": "2026-10-11T14:30:00.125+09:00",
    "text": "공개 게시물 원문"
  }]
}
```
외부 AI를 명시적으로 사용하는 경우 `/api/ai/results`에도 같은 `session_id`가 필요합니다.
첫 초기화 전 기존 API 입력 방식은 유지됩니다. **새 시연 이후 ID 없는 API 입력은 HTTP 409로 거부됩니다.**

## 보존 기록 확인
원래 DB와 `_sessions` 폴더에 각 시연이 남아 있고, 각 새 DB의 `metadata.previous_demo_db`에 바로 이전 저장소 경로가 기록됩니다. 이 파일들은 서버를 중지한 상태에서 함께 백업하세요. `.active.json`을 임의 삭제하면 원래 DB로 돌아가므로 삭제하지 마세요. 기록 선택·복원 UI는 이번 변경에 포함하지 않습니다.

Python 전체 테스트 115개, 알림 상태 테스트 9개, React 빌드 통과. 실제 브라우저에서 취소 시 유지, 새 시연 후 0건, 새 수집·알림 재개와 재초기화를 확인했습니다. 독립 검토에서 발견한 JSONL 부분 기록 재유입 문제를 수정하고 회귀 테스트를 추가했습니다.
